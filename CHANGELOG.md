# Changelog

All notable changes to this project are documented in this file.
Format follows [Keep a Changelog](https://keepachangelog.com/). Versions follow Semantic Versioning.

## [Unreleased]

### Added
- Invitations v2 (BE-010, DEC-020): an invitee who already has an identity now accepts by signing in and confirming — no second password. Accepting while signed out answers 403 `INVITATION_LOGIN_REQUIRED`; accepting while signed in as a different identity answers 403 `INVITATION_IDENTITY_MISMATCH`. New public `GET /api/v1/invitations/preview` describes a pending invitation (agency, kind, roles, identity state) for the accept screen.
- Portal invite-link (BE-010, DEC-020): granting Portal access to a brand-new email now sends a client invitation link (the invitee sets their own password when accepting) instead of the agency setting an initial password — this supersedes DEC-009 point 6. The invitation email reuses the existing template with Portal wording. Granting access to an existing identity still creates the client membership immediately, and rule Q3 is enforced at every membership-creation point.
- Ownership transfer (BE-010, DEC-020): `POST /api/v1/ownership/transfer` — the current Owner hands the Owner role to another active staff membership atomically (role removed and granted in one transaction, both memberships' tokens revoked), keeping the invariant of exactly one Owner per agency. New tests: `InvitationV2Test` and `OwnerInvarianceTest` (13 cases).
- Data display convention (DEC-021): desktop lists switch to modern tables when they have at most 6 core columns (per-column max-width, no horizontal overflow ever), cards stay on mobile and for long or heterogeneous content; skeleton loading states become mandatory for data regions (geometric twins of the real content, fixed count, appear only after ~200 ms, filter changes keep previous data). Recorded in `docs/UI_GUIDELINES.md` sections 3 and 9; the conversion of existing screens is task FE-019.
- Data display system (FE-019, DEC-021): shared `DataTable` and `Skeleton` components; Clients, Projects, team Members and Workload lists plus the task list inside project detail now render as modern desktop tables (at most 6 core columns, per-column widths with ellipsis, never any horizontal overflow) while mobile keeps the existing cards; first loads show geometric skeleton twins (fixed count, appear only after ~200 ms, reduced-motion safe) and filter changes keep the previous data with a subtle busy dim instead of blanking the list. The project detail page no longer unmounts during refetches.
- Cross-tenant isolation sweep v2 (QA-006): rewritten for the DEC-018 membership model — foreign agency ids on 62 authenticated ID-bearing routes return 404, foreign references in request bodies return 422 `CROSS_TENANT_REFERENCE`, list endpoints exclude foreign records, Portal tokens only see their own client's projects; plus the three DEC-018 scenarios (one identity in two agencies isolated by token; select/switch to a membership the identity lacks is rejected; deactivated membership loses access immediately) and the BE-010 surfaces (invitation resend/revoke, ownership transfer with a foreign membership). File: `tests/Feature/Security/CrossTenantIsolationTest.php` (22 tests, 98 assertions); whole suite 129 PASS, Pint PASS; no leak found.

### Changed
- Web run mode is now switchable (CHORE-001): `docker-compose.yml` takes `WEB_MODE` — default `dev` (hot reload, per-route/per-locale compiles), `WEB_MODE=prod docker compose up -d web` runs a production build for acceptance testing, where page transitions no longer pay dev-mode compile time.
- Consistent row/card navigation (FIX-020 part 1, DEC-023): every data table row and data card with a detail screen now navigates by clicking the whole row/card — the project task table and its mobile cards, the Projects/Members mobile cards, Team cards and the Workload list (to the member detail) were aligned with the Clients/Projects/Members tables; titles are plain text instead of separate links/buttons, and the redundant "Detail" item leaves the kebab menus (actions only), which also removes the Members table's now-empty action column. CRM Kanban cards are the deliberate exception (drag-to-move pipeline stages; the title link stays).
- Assigned teams are now visible on the project detail page (FIX-021, PO-approved option A): the team assignment section shows an "Assigned teams" chip row (team name + contributing member count, derived from each member's `via_team_id`, with an explicit empty state), and members who joined through a team carry a small team-name label on their member chip. The member payloads (`ProjectMemberController` list and `ProjectResource`) now expose `via_team_id` so the information survives reloads.

### Fixed
- Data display polish (FIX-019, DEC-022): table headers now render at 11 px on a single line with ellipsis instead of wrapping and inflating the header row; task Priority is a semantic colour chip (urgent red, high rose, medium amber, low slate) in the project task table, the mobile task cards and the task detail field; nested borders are removed on the project detail page (one border level per data block — the Tasks table and the milestone / mobile task items drop their own frames inside their section cards and keep hairline dividers only, via the new `framed` prop on `DataTable`); the project detail first-load skeleton is now a geometric twin of the real layout, including a true table skeleton for the Tasks section, and follows the same ~200 ms appearance rule as the list pages.
- Kebab action menus are no longer clipped by framed tables (FIX-020 part 2, DEC-024): the shared `ActionMenu` renders its menu through a portal with fixed positioning anchored to the toggle button, flips upward near the viewport bottom and keeps its position on scroll, so menus on the last table rows display in full instead of being cut off by the table frame.

Implementation follows in BE-008.

### Changed
- One identity for everything (DEC-018, BE-009): users no longer belong to a single agency — memberships carry the per-agency kind (`staff`/`client`), roles, job title, phone and active flag. Portal access is a client membership on the same identity (same email and password as the internal app); Sanctum tokens are bound to a membership and the active agency is always derived from the token server-side. Tenant scoping is now fail-closed: business models throw `TenantContextMissing` when queried without a tenant context instead of running unscoped. Inviting an email that already has an identity now links the invitation to that identity (`ALREADY_MEMBER` when already an active staff member here); granting Portal access to an existing identity no longer creates a second account. New error codes: `NO_ACTIVE_MEMBERSHIP`, `MEMBERSHIP_INACTIVE`, `TENANT_CONTEXT_REQUIRED`, `STAFF_CLIENT_MEMBERSHIP_CONFLICT`, `ALREADY_MEMBER`. Deleting a client now deactivates its Portal memberships and revokes their tokens.

### Removed
- The separate `client_accounts` table and `clients` auth provider/broker (DEC-018): Portal sign-in, forgot/reset password run on the single identity via the `users` broker.
