## [Unreleased]

### Added
- Portal collaboration UI (FE-023): Portal dashboard and project detail with Files/Discussion/Approvals/History, internal project "Client Portal" section with visibility toggles, files, thread, approvals and history, plus notification render cases for portal comment/approval response.
- Client Portal & Collaboration (BE-011, DEC-028): milestones and tasks gain a per-item `client_visible` flag (default visible, set through the existing PATCH endpoints) and the Portal now computes progress over the visible subset only, with draft/cancelled projects hidden from the Portal entirely. Two-way file sharing on the private disk (`project_files`): staff and clients upload to a project (20 MB cap and an extension allowlist in `config/portal.php`), downloads stream through authorized endpoints, hidden staff files are invisible to clients. A single per-project discussion thread (`portal_comments`, deliberately separate from internal task comments) connects clients and staff. Approval requests (`approval_requests`) cover a file, a milestone or a written hand-over: clients approve or request changes (comment mandatory), the first response wins and is immutable (`APPROVAL_ALREADY_RESPONDED`), and any portal account of the client record may respond. New `GET /portal/dashboard` aggregate (projects, pending approvals, unpaid balance, recent files) and a communication history composed at read from comments, approvals and public invoice events — no activity table. The Notifier gains `portal.comment` (project manager + project members) and `portal.approval_response` (request creator + project manager), in-app only — clients get no email in the MVP. Two new permissions, `portal.files.manage` and `portal.approvals.manage` (Owner/Admin/Project Manager); replying in the thread needs only `projects.view`.
- Language toggle (FE-022): a circular flag button next to the notification bell in the staff Topbar switches EN/VI in place (reusing the existing locale-switch logic), with inline SVG flags (no emoji or external assets) and a new `Common.switchLanguage` key.
- Notifications UI (FE-021): bell icon with unread badge in the app shell (Topbar), dropdown panel (latest 10, mark-all-read, deep links) rendered through a portal anchored to the bell, plus a full `/notifications` page with unread filter and shared Pagination; all copy via `Notifications.*` (EN + VI) rendered from `type` + `data`, plus a `bell` icon added to the shared Icon set.
- Workflow & Notifications (BE-009, DEC-026): in-app notifications on a custom tenant-scoped `notifications` table (unique `dedupe_key`), created through one `Notifier` service for task assignment/reassignment, task status changes, task comments and invoice status transitions (including payment-driven Paid and Paid→Sent reverts), with email only for task assignment and invoices reaching Paid (queued job, recipient's stored locale); read API (`GET /notifications` with unread filter, unread-count, mark read / mark all read) pinned to the token identity and agency; a daily `reminders:run` scheduler command evaluating due/overdue tasks and milestones, 3-day-stale leads and overdue invoices per agency timezone (invoice reminders go to Accountants and the Owner only, never to clients), pruning notifications older than 90 days. Tasks and invoices gain a nullable `created_by` column so the creator recipient rules have data.
- Agency payment details can now be read back (FIX-031): `GET /agencies/{id}/payment-details` under the same Owner/Admin permission and response shape as the PATCH endpoint, so the settings form prefills the saved bank/VietQR details instead of opening empty.

### Changed
- Portal accounts section on the client detail page tidied (FIX-035): each account row is now a compact three-zone layout (two-line identity with avatar, status chip with last-login meta, actions), the Deactivate action is a highlighted danger-soft button with a lock icon instead of a plain text link, and the danger-button rule (highlight dangerous actions — tinted red background, red border and text, icon where sensible — never plain text) is recorded in `docs/UI_GUIDELINES.md` section 7.

### Fixed
- FIX-038: Acceptance round-2 follow-ups and pagination completion — the task detail page gains the row actions it was missing (header kebab with Portal visibility toggle and Delete, gated by `can_act` and the tasks.update/tasks.delete permissions); the Files tab no longer breaks on mobile (file names truncate in a flexible column, uploader names are semibold, Download/Delete move into a dropdown menu while the Portal visibility eye stays on the card, on both the internal and Portal sides); the Approvals tab drops its nested borders (soft-background create form, divider-separated approval list). Pagination is now complete: Clients, Members, Teams and Invitations lists get full page controls (new meta-returning Page helpers, filters reset to page 1), the Leads Kanban board loads the API cap of 100 instead of silently truncating at the default page size of 15, and every sub-list (tasks, milestones, portal files/comments/approvals/history on both sides, checklist, task comments, contacts, notes, activities, payments, Portal invoices, tags, directory users) requests `per_page=100` so nothing is silently cut at 15 records.

- Invoices now reject a project that belongs to a different client (FIX-031): `invoice.project_id` must belong to the invoice's `client_id` on create and update (a project of another client in the same workspace answers 422 `PROJECT_CLIENT_MISMATCH`; a project from another workspace still answers 422 `CROSS_TENANT_REFERENCE`).
- Task detail gating (FIX-033): the task detail page now honours `can_act` (locking status select, checklist add/toggle/delete and comment form for non-actors with an in-place note), avoids full-page 403 banners from secondary requests, deep-links task notifications to `/projects/{id}/tasks/{taskId}`, and gives the description a distinct background.
- Task action scope (FIX-033, DEC-027): acting on a task — update, delete, comments, checklist — now requires being the task's assignee, the project's manager, or holding the Owner / Admin / Project Manager role on the current membership; denials answer 403 `TASK_ACTION_FORBIDDEN` instead of passing on role permission alone, and task payloads gain a `can_act` flag computed by the same rule so the FE can gate its controls.
- Team tab scrollbar and bell button chrome (FIX-034): removed the stray vertical scrollbar on the Team tab nav (`overflow-y-hidden` alongside `overflow-x-auto`) and dropped the border/box from the notification bell button in the Topbar.

## [0.7.0] - 2026-11-27

### Added
- Invitations v2 (BE-010, DEC-020): an invitee who already has an identity now accepts by signing in and confirming — no second password. Accepting while signed out answers 403 `INVITATION_LOGIN_REQUIRED`; accepting while signed in as a different identity answers 403 `INVITATION_IDENTITY_MISMATCH`. New public `GET /api/v1/invitations/preview` describes a pending invitation (agency, kind, roles, identity state) for the accept screen.
- Portal invite-link (BE-010, DEC-020): granting Portal access to a brand-new email now sends a client invitation link (the invitee sets their own password when accepting) instead of the agency setting an initial password — this supersedes DEC-009 point 6. The invitation email reuses the existing template with Portal wording. Granting access to an existing identity still creates the client membership immediately, and rule Q3 is enforced at every membership-creation point.
- Ownership transfer (BE-010, DEC-020): `POST /api/v1/ownership/transfer` — the current Owner hands the Owner role to another active staff membership atomically (role removed and granted in one transaction, both memberships' tokens revoked), keeping the invariant of exactly one Owner per agency. New tests: `InvitationV2Test` and `OwnerInvarianceTest` (13 cases).
- Data display convention (DEC-021): desktop lists switch to modern tables when they have at most 6 core columns (per-column max-width, no horizontal overflow ever), cards stay on mobile and for long or heterogeneous content; skeleton loading states become mandatory for data regions (geometric twins of the real content, fixed count, appear only after ~200 ms, filter changes keep previous data). Recorded in `docs/UI_GUIDELINES.md` sections 3 and 9; the conversion of existing screens is task FE-019.
- Data display system (FE-019, DEC-021): shared `DataTable` and `Skeleton` components; Clients, Projects, team Members and Workload lists plus the task list inside project detail now render as modern desktop tables (at most 6 core columns, per-column widths with ellipsis, never any horizontal overflow) while mobile keeps the existing cards; first loads show geometric skeleton twins (fixed count, appear only after ~200 ms, reduced-motion safe) and filter changes keep the previous data with a subtle busy dim instead of blanking the list. The project detail page no longer unmounts during refetches.
- Cross-tenant isolation sweep v2 (QA-006): rewritten for the DEC-018 membership model — foreign agency ids on 62 authenticated ID-bearing routes return 404, foreign references in request bodies return 422 `CROSS_TENANT_REFERENCE`, list endpoints exclude foreign records, Portal tokens only see their own client's projects; plus the three DEC-018 scenarios (one identity in two agencies isolated by token; select/switch to a membership the identity lacks is rejected; deactivated membership loses access immediately) and the BE-010 surfaces (invitation resend/revoke, ownership transfer with a foreign membership). File: `tests/Feature/Security/CrossTenantIsolationTest.php` (22 tests, 98 assertions); whole suite 129 PASS, Pint PASS; no leak found.
- Finance & Billing API (BE-008, DEC-019): invoices with line items and stored totals (one optional tax rate), per-agency auto invoice numbers `INV-{YYYY}-{seq}` assigned at creation and never reused, stored statuses draft/sent/paid/cancelled with Overdue derived at read (plus `stored_status` and a working `?status=overdue` filter), Draft-only editing and Owner-only Draft deletion, sending requires at least one line item; manual payments on sent invoices (partial payments accumulate, overpayment rejected with `OVERPAYMENT_NOT_ALLOWED`, full coverage flips the invoice to Paid automatically, deleting a payment recomputes balance and status); PDF export via dompdf with DRAFT/CANCELLED watermarks; agency bank/VietQR payment details editable by Owner/Admin via `PATCH /agencies/{id}/payment-details` and shown on invoices and PDFs; read-only Portal invoice list/detail scoped to the client's own invoices; project detail gains read-time `invoiced_total`, `collected_total` and `remaining_budget` reconciliation figures. New error codes: `INVOICE_EMPTY`, `INVOICE_NOT_EDITABLE`, `CANNOT_CANCEL_INVOICE`, `CANNOT_DELETE_INVOICE`, `PAYMENT_NOT_ALLOWED`, `OVERPAYMENT_NOT_ALLOWED`.
- Multi-agency sign-in and workspace switching (FE-014, DEC-018): sign-in with several eligible memberships now offers a centered workspace picker backed by a short-lived selection token (kept out of the app-token cookie), while an agency switcher under the sidebar logo lists active staff memberships with localized role chips and reloads the dashboard under the newly selected agency; both English and Vietnamese copy are included.
- Invitation acceptance v2 (FE-015, DEC-020): both internal and Portal accept screens now preview the invitation and branch into four states — new email sets a password, an existing identity signs in first, a matching session confirms without a password, and a mismatched session shows a clear error; Portal grants to new emails now appear as pending invitations while existing identities get immediate access, with English and Vietnamese copy.
- Multi-agency identity regression sweep (QA-007): Playwright API spec `tests/e2e/multi-agency-identity.spec.ts` covering login with multiple memberships (selection token), select-agency, foreign membership rejection (404), switch-agency token revocation and Portal client login, plus PHPUnit `LastMembershipAutoSelectTest` for re-login auto-select by last_membership_id; all cases PASS. No BE/FE code changes.
- Finance & Billing UI (FE-020): added internal invoice list/detail/create/edit, manual payment recording with overpayment guards, PDF export, agency payment-details settings, project budget reconciliation, and read-only portal invoices, with BFF proxies, i18n, and ConfirmDialog-based destructive actions.

### Changed
